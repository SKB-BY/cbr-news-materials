## Реестр companies.csv

Рабочий реестр — карта сил, а не полный перечень всех фирм. В нём четыре группы:

1. **Программы и инициативы** (`kind=program`) — Replicator, JCO, European Drone Defence Initiative, GCAP.
2. **Организации** (`kind=agency`) — государственные, некоммерческие и структуры НАТО/ЕС. Часть из них — аналоги DARPA (DARPA, IARPA, DIU, AFWERX, AID, DASA, Brave1 и др.); часть — заказчики, закупочные агентства и лаборатории (DGA, NSPA, MCWL и др.).
3. **Компании США, Европы и Украины** (`kind=company`, `region` = `US` / `Europe`).
4. **Субъекты вне США/Европы** (`region=outside`) — компании Турции, Израиля, Китая, встретившиеся в ленте, а также российские и иранские компании как **объекты анализа угроз и картирования цепочек поставок**.

Реестр **не является** перечнем организаций, подчинённых DARPA, и не ограничивается подрядчиками США и Европы.

- Колонка `sponsor` заполняется только для `kind=agency` и `kind=program` (вышестоящее ведомство или учредитель). У `kind=company` это поле пустое.
- Заказчики — только в `customers` + `customers_source` и только при наличии источника.
- Российские и иранские компании не подчинены DARPA и не входят в контур программ DARPA (каталог `darpa-programs/`).

### Колонки

| Колонка | Что содержит |
|---|---|
| `kind`, `region`, `country`, `name` | тип записи, регион (`US`, `Europe`, `NATO/EU`, `outside`), страна, название |
| `sponsor` | только для агентств и программ: вышестоящее ведомство / учредитель |
| `role_focus` | роль организации или профиль компании |
| `url`, `source_url` | официальный сайт и страница, подтверждающая строку |
| `customers`, `customers_source` | заказчики — только с источником |
| `ubo_name`, `ubo_source` | материнская компания или конечный бенефициар — только с источником; пусто, если источника нет |
| `red_flags`, `red_flags_source` | маркеры риска (например, санкционный список) — только с официальным источником; пусто значит «маркера с источником нет», а не «чисто» |
| `tier_level` | рабочая классификация уровня в цепочке поставок (см. ниже); пусто — не классифицировано |
| `url_http`, `url_title`, `verified_at` | результат открытия официального URL на дату проверки (UTC) или пометка, почему страница не открылась |
| `mentions`, `mention_examples` | число упоминаний в живой базе по узкому шаблону названия и до трёх примеров |
| `id` | служебный идентификатор строки (для карты и скриптов) |

### Tier — рабочая классификация

- **Tier 1** — прямой подрядчик министерства обороны / прайм. Проставлен только строкам, которые реестр уже относит к праймам.
- **Tier 2** — ключевой поставщик систем и подсистем для интеграторов (сенсоры, обработка сигналов, навигация, автопилоты).
- **Tier 3** — производитель компонентов (чипы, двигатели, композиты).

Если уровень нельзя обосновать, поле остаётся пустым.

## Онлайн-карта

[skb-by.github.io/cbr-news-materials/map/](https://skb-by.github.io/cbr-news-materials/map/) — статическая страница (GitHub Pages, ветка `main`, корень репозитория). Карта на [Leaflet](https://leafletjs.com) 1.9.4; библиотека лежит в репозитории (`map/vendor/`), сборка не нужна. Подложка — тайлы OpenStreetMap (светлая приглушённая, стандартная и тёмная — переключатель справа вверху). Виджет атрибуции Leaflet в правом нижнем углу отключён (`attributionControl: false`); лицензионная подпись OpenStreetMap дана обычным текстом внизу боковой панели.

- Точки — все строки `companies.csv`, по стране (не по адресу). Легенда разделяет программы, организации, компании США/Европы/Украины, компании вне США/Европы и объекты анализа угроз (Россия, Иран); у последних — отдельный знак и пояснение в информационном окне. В окне точки — страна, профиль, сайт и источник, заказчики, владелец / UBO, маркеры риска, tier и связи.
- Связи — только с основанием в реестре и URL источника ([map/links.json](map/links.json)): структура агентств и программ, заказчики, владельцы / материнские компании. Красное кольцо — маркер риска с источником.
- Обновление данных карты: `python3 scripts/build_map_data.py` (читает `companies.csv` и `map/links.json`, пишет `map/data.js`).

## Разрыв упоминаний (mention gap)

```
python3 scripts/mention_gap.py --csv companies.csv --out-csv data/mention_gap.csv --out-md data/mention_gap.md
python3 scripts/mention_gap.py --csv companies.csv --db news.sqlite --min-items 2 ...   # с живой базой
```

Скрипт (только стандартная библиотека Python) извлекает кандидатов в названия организаций регулярными выражениями из `mention_examples` и, при указании `--db`, из заголовков и вводных абзацев новостей; сравнивает с реестром (названия, псевдонимы, узкие шаблоны упоминаний агрегатора, если доступен `companies_data.py`). Результат — **рабочий список кандидатов, не проверенная перепись**: в нём есть ложные срабатывания (продукты, мероприятия, общие слова). В реестр ничего автоматически не добавляется — строка вносится только после открытия официального сайта и источника. Текущий файл [data/mention_gap.md](data/mention_gap.md) построен по живой базе на 11.11.2026.

## Правило слухов

- Слух — одна цепочка без второго независимого источника.
- Заявление — названа организация, но источник один.
- Новость — подтверждена хотя бы одним независимым изданием (не перепечатка).

## Что не публикуется

Живая база и архив (SQLite), токены и служебные ключи в этот репозиторий не входят. Статистика по базе не публикуется.

Сбор ведётся только из открытых источников (сайты и публичные страницы t.me/s). Время материалов — Europe/Minsk.
